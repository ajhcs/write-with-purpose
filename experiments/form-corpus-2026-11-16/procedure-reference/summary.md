The records describe web pages, not whole manuals or independent authors.

Django, MDN, Canonical LXD and Kubernetes are distinct maintained documentation projects, but all concern software and are not a representative cross-domain sample. We have not established that any page is highly read, highly cited, or exemplary. The title screen explicitly removes obvious navigation indexes, a contributor template, an introduction, and evident procedure or conceptual pages located in reference; it does not certify other pages. Individual pages can combine explanation, tasks, API lookup, or indexes. Some Django pages are large composite manuals, while MDN includes much smaller lookup units, so they are not exchangeable. Project and individual records must be inspected before interpretation; preserve the projects and individual page patterns rather than using their pooled median as a template.

## Sources, rights, and procedure

Definitions are used as scoped discovery aids: [Diátaxis how-to guides](https://diataxis.fr/how-to-guides/) and [reference](https://diataxis.fr/reference/), and the [DITA information types](https://docs.oasis-open.org/dita/v1.2/os/spec/archSpec/dita_technicalContent_InformationTypes.html). These do not establish genre fitness or numerical targets. Candidates were discovered from [Django's English sitemap](https://docs.djangoproject.com/sitemap-en.xml), filtered to the published `/en/6.1/howto/` and `/en/6.1/ref/` paths, [Canonical LXD’s sitemap](https://canonical.com/lxd/docs/latest/sitemap.xml), [Kubernetes English sitemap](https://kubernetes.io/en/sitemap.xml), and [MDN's English sitemap](https://developer.mozilla.org/sitemaps/en-us/sitemap.xml.gz), filtered to `/How_to/`, task-verb `/Guides/`, and `/Reference/`. LXD `/howto/` and `/reference/` and Kubernetes `/docs/tasks/` and selected `/docs/reference/` paths supplement these, excluding the Kubernetes generated API paths. MDN guide titles are a weak task proxy; the selection excludes many potentially useful how-tos whose titles do not match the selected verbs. Candidate ranking interleaves URL groups deterministically, not popularity, quality, topic prevalence, or random selection. Mechanical checks require a title, main body, canonical URL matching the final URL (or the final URL where Kubernetes has no canonical link), at least 80 prose words, five captured blocks, and code no more than three times prose plus list words. These filters exclude short valid references and can retain invalid pages.

Each attempted record contains its URL, extracted title, project/collective author, publisher label, known version or live status, page time/sitemap date when exposed, retrieval time, HTML SHA-256, license reference, extraction scope, eligibility result, and measures. Dates are first HTML `time` or sitemap `lastmod`, not verified publication dates; missing dates are explicitly recorded. The digest identifies the response captured in this run, including potentially changing page chrome, and does not establish an immutable revision. Django's [BSD-3-Clause license](https://github.com/django/django/blob/main/LICENSE), [MDN's content license guidance](https://developer.mozilla.org/en-US/docs/MDN/Writing_guidelines/Attrib_copyright_license), [Canonical LXD’s AGPL-3.0 terms](https://github.com/canonical/lxd/blob/main/COPYING) and [Kubernetes CC BY 4.0](https://github.com/kubernetes/website/blob/main/LICENSE) are linked per source; source-specific attribution and exceptions apply. No complete source pages are redistributed. `*-candidates.json` is discovery metadata; `*-records.jsonl` includes rejected attempts; `aggregate.json` contains derived descriptive statistics; `collect.py`, `supplement.py` and `summarize.py` reproduce the selection and calculations against whatever the live sites serve on rerun. Execution reads remote content and does not execute it. HTTP traffic is limited to eight concurrent requests for initial collection and six for supplemental collection. Live pages and sitemaps can change, so hashes and results may differ on rerun.

The extractor uses Python's HTML parser and captures outer `p`, `li`, `pre`, `table`, `figure`, and h1–h6 blocks in `main` (or LXD’s `article role=main`), excluding scripts, style, navigation, aside and footer. Nested blocks are captured once; nested list markup can cause undercounting and paragraphs inside list items count as list content. Inline code inside prose remains prose; regex tokenization splits some non-ASCII technical text, and punctuation-based sentence segmentation is approximate. HTML page chrome or generated content inside `main` can leak into counts. No rendered-page comparison has been performed. These limits and the mechanical code-volume threshold require an independent extraction audit before comparative inference.

## Historical-version pilot

Seven additional Python 3.4 HOWTO pages were measured separately in `procedure-historical-records.jsonl` using `historical.py`. They are **not included** in the table or pooled statistics above. The archived documentation identifies itself as version 3.4.10; Python's [3.4.10 release page](https://www.python.org/downloads/release/python-3410/) dates that release to March 2019. This is a pre-2020 version anchor, not proof that each page was written or published before 2015, nor proof that the current archived HTML has never changed. The `requested_url` and response hash identify the archived page; its declared canonical link points to current Python documentation and is preserved separately. As with the primary collection, the HOWTO label does not establish that each entire page is a procedure. Django 1.7's tested documentation endpoint returned 404; it was not fabricated or counted. The four-project main collection consists of current or date-unknown live versions and should not be described as a historical corpus.

## Persisted screening decisions

Each JSONL record now carries `title_screen_status`, `included_in_analysis`, and `exclusion_reason`. The existing `accepted` field reports **mechanical extraction eligibility only**; it does not mean the page passed the later title screen. A `passed_limited_title_screen` status still does not establish full genre eligibility. Historical-pilot records are explicitly excluded from the main aggregate. Run `annotate_records.py` after any collection or historical-pilot rerun and before `summarize.py`; the latter derives the main analysis directly from the persisted inclusion flags. Reannotation and aggregation require no network. A consistency check confirmed 222 procedure and 216 reference records included, matching `aggregate.json`.
