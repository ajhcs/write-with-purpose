# Round 1: Computable checks, rule execution and evaluation

The strongest opportunity is to make a chosen improvement **executable and falsifiable**: identify the reader problem, make the actual change, compare its effect with the original, and check declared constraints on the delivered artifact. Mechanical evidence and editorial judgment must remain separate. These are candidate mechanisms, novel combinations relative to the inspected local baseline, not demonstrated improvements or claims about all writing products.

The current writer already proposes deletion/movement comparisons and a reader edit; the editor uses the smallest set of changes that addresses the problem, then rereads the passage. `check_text.py` 0.2.0 can enforce only declared exact literal counts, maximum whitespace-token words and maximum growth against a source; its numeric multiset changes, exact duplicate blocks, explicit markers and limited Markdown anchors are advisory. An exit code of zero without enforcement is not a clean editorial verdict. `edit_locally.py` 0.1.0 binds nonoverlapping exact code-point edits to source-byte SHA-256, writes a separate output and measures lexical change, but does not establish correctness or usefulness. The calibration checker validates binding, fields and anchor identity, not function adequacy; its experimental schema cannot represent conflicting decisions for separate instances of a single function in a paragraph. These existing tools do not execute a reader task, compare semantic gains, or validate a planned improvement.

## CE-01: Execute the proposed repair, then try to recover the intended result

**Behavior.** For a material improvement request, select a named reader failure and a specific intervention (move the answer earlier, make a missing relation explicit, replace an inventory with its supported relationship, or preserve a useful scene while reorganizing). Construct an actual candidate—not merely a plan—and compare the original and candidate by trying the same concrete reader task with each. Identify the information the reader could recover before and after and the necessary context lost or added. Keep the candidate if it is a defensible improvement within the author’s request; retain the original if the proposed change fails. When a broader rewrite is authorized, allow coordinated paragraph or section changes, rather than optimizing local edit size. For narrow correction-only tasks, do not expand scope.

**Roles.** Model identifies the task and performs this provisional comparison; the author supplies missing intentions or chooses among materially different valid directions when needed. Existing edit tool can reconstruct exact selected changes for saved UTF-8 inputs, but whole-passage rewrites can use a separate candidate and comparison mode. Neither tool simulates a real reader. The reader-task exercise is an evaluable hypothesis; independent readers and author preferences decide whether the supposed gain holds.

**Example.** A decision memo hides its recommendation behind background. Move the existing recommendation above the supporting detail, then test whether a reader can identify the proposed choice and its qualifying condition from the opening. A misleadingly decisive opening that drops the condition fails despite faster recovery. **Counterexample:** a reflective essay intentionally postpones its insight; moving the conclusion first may destroy the experience the author intended.

**Difference and change.** Existing `structure-and-purpose.md` already says to try removal or movement; this mechanism requires a *specified reader task and before/after observable* when substantial improvement is requested, and gives permission for a coordinated restructuring. Retire any interpretation of `edit-with-purpose`'s “smallest set” as a minimization objective across all intervention levels. The request still bounds scope. Test against the original workflow on fresh varied tasks; independently judge improvement, source fidelity, author preference and time. No aggregate quality score.

## CE-02: Constraint-to-artifact receipt, with a semantic remainder

**Behavior.** Before delivery, translate only explicit, mechanically expressible obligations into the existing checker's contract; check the actual final artifact after the last edit, inspect enforcement status, and repair only actual violations. Bind each receipt to the artifact hash. Keep a separate short list of obligations code cannot determine—such as whether a preserved quotation still supports the same claim—and review them in context. If a publisher’s counted scope excludes headings or code, isolate that scope and disclose that whitespace-token counting may differ from its counter. No declared ceiling means no invented ceiling.

**Roles.** Model translates task obligations and reviews context; code checks current exact literals and word/growth limits, and records numbers and other advisories; author supplies or resolves actual conflicts. A file check is not a chat interception hook; a final chat answer requires a corresponding available counter or an honest limitation. A literal surviving somewhere, a matching numeric multiset, a successful exit or a valid anchor never proves correct meaning.

**Example.** Brief says “retain this exact quotation and keep the body under 250 words.” Check the isolated body against the explicit literal and ceiling; inspect the quotation’s attribution and whether it remains attached to the same claim separately. **Counterexample:** “preserve the idea” is not an exact-quotation requirement, and a protected literal inside a code example may satisfy the current raw-file count without fulfilling a prose-placement requirement. That placement requires manual inspection or new scope-aware code.

**Difference and change.** The existing guide already requires checking explicit ceilings; this adds a compact mapping of each actual obligation to the final-byte receipt **or semantic remainder**, rather than equating a checker pass with completion. Retire generic “all checks passed” when any check is unavailable, advisory or out of scope. Test stale-file rejection at the orchestrator level, scope mismatch and semantic false positives; artifact hashes exist, but the proposed automatic linkage/guard is not implemented.

## CE-03: Competing moves with an explicit loss, not an edit-size score

**Behavior.** When a requested improvement has a consequential choice (keep/move/delete, local repair versus section reorganization, explanation versus example), materialize a small set of distinct alternatives including the original. For each, record one intended gain and the strongest specific loss or unresolved meaning risk, then choose according to the author’s task; retain more than one when legitimate goals conflict. Use an edit plan as an execution record, not as a plan-approval pause or a prohibition on broad edits. Do not generate routine alternatives for a clear typo or an already adequate passage.

**Roles.** Model generates and compares alternatives, preserving original supported facts; author chooses when objectives or voice cannot be inferred. `edit_locally.py` can construct separate nonoverlapping source-bound candidate files and expose selected blocks and token changes; a move or broad restructure may require a replacement or comparison mode, whose outside-span preservation is explicitly not assessed. Code does not measure originality, merit or whether a new inference is valid.

**Example.** A tutorial repeats a prerequisite. Candidate A deletes the second occurrence and improves brevity; candidate B keeps it at a second independent entry point. Prefer B if readers enter at that step; prefer A if the sequence is linear and task constraints demand concision. **Counterexample:** shortening a repeated warning used at separate hazardous steps could harm usability; preserving it is productive repetition, not a failure to edit.

**Difference and change.** Current writing guidance already invites local deletion comparison. The new mechanism makes the **loss of each alternative** explicit, compares competing levels of intervention and makes the original an eligible outcome. Retire “fewest changed words wins” or word-count reduction as a proxy for good editing; existing measurements were never intended as scores. Test on author-reviewed, independently held-out examples with edits judged for useful improvement, meaning retention and reviewer burden, not lexical distance as a success criterion.

## CE-04: Test disagreement and real gains separately; stop on an issue-based condition

**Behavior.** For a new or revised semantic rule, freeze its trigger, positive and counterexample, expected reader task and decision method before evaluating on fresh documents. Keep independent assessments and unknown/unresolved states, and compare exact sets, partial overlap and positive-label marginals where appropriate; inspect actual disagreements and relational targets instead of maximizing a single score. For editorial impact, separately compare baseline versus candidate on reader task success, author preference, factual fidelity and time/burden using a design suited to the task and document clustering. Avoid universal thresholds. For ordinary editing, stop once the requested intervention and relevant checks are complete and no named unresolved issue justifies another pass; a model disagreement by itself triggers inspection, not automatic rewriting or consensus loops.

**Roles.** Model proposes and implements a candidate; code validates schemas, exact anchors and offset bounds only where supported; independent human reviewers/readers judge boundary adequacy, target meaning, factual correctness and task outcomes; author controls final tradeoffs. `profile_sources.py` explicitly flags 97 PERSUADE rows with bounds issues in its local diagnostics; repairs must remain unresolved or excluded pending source interpretation. Its GUM parser treats structural `span` separately from semantic edges. These parsers are evidence-handling infrastructure, not meaning classifiers.

**Example.** In a prospective fresh test, compare two instructions that clarify a procedure; readers attempt the actual task and report confusion while reviewers assess whether the steps preserve source constraints. Keep raw assessments and rejected alternatives. **Counterexample:** two coders agree on an empty set because both missed a relation; high agreement does not show successful teaching or valid boundaries. A precise quote can still be a partial evidence anchor rather than the entire realization.

**Difference and change.** Existing calibration reports exact sets, partial overlap and checks, but it did not evaluate author or reader gains; here rule-level reproducibility and task-level benefit become separate test questions and execution stops on a named failure, rather than a fixed number of passes. P18’s 908 fixed-sentence study does not validate our paragraph boundaries; local 21/36 versus 18/36 exact agreement showed no gain and no semantic gold. Its 3.04× JSON size measures artifact volume, not actual cost. Test feasibility and bias before claiming a reduction in burden or an advantage. Do not make the study's sample-specific observations acceptance thresholds.

The nine accepted feature groups remain observations and diagnostic inputs. F01–F06 can help expose scope and distribution; F07/F08 distinguish support placement and visible presentation; F09 remains a context-dependent semantic layer. No feature is a quality score, mandatory label quota, or empirical writing limit. We should not demand full function annotations before an ordinary correction or turn every suggestion into a mandatory author decision.
