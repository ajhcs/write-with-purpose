# Technical documentation reuse: evidence map

16 November 2026. Eight primary-source records appear in `findings.json`. This is a targeted evidence map, not a completed systematic review. Source labels are retained; proposed mappings to project features are hypotheses, not adopted rules. Titles, steps, semantic arguments and section roles are different units.

## Three strongest opportunities

1. **Reuse README section classifications and the published coding guide.** [Prana et al.](https://ctreude.ca/pdf/categorizing-the-content-of-github-2019.pdf) supply the exact labels **What, Why, How, When, Who, References, Contribution, Other** in Table 2, with illustrative headings and disagreement resolution. Their [combined CSV](https://raw.githubusercontent.com/gprana/READMEClassifier/master/input/dataset_combined.csv) contains section IDs, repository URLs, headings and codes receiving at least two votes. The raw file includes rows marked `-`, so the published count of 4,226 sections / 393 repositories must not be equated to every row. The sample excludes short READMEs, nonsoftware repositories and non-English material. The automated classifier combines Why with What and includes Exclusion; retain the original taxonomy for human coding. The reported kappa is 0.858 for two annotators, with third-rater resolution. Use this as a README-specific F02/F09 pilot and a source of counterexamples, not as a mandate to include each role. Whole-document F03/F08 analysis requires matching exact archived files and checking section extraction, source permissions, boilerplate and duplicate projects.

2. **Reuse semantic annotation conventions for procedures.** The [WLP 2018 paper](https://aclanthology.org/N18-2016.pdf) includes an appendix with annotation guidance and measured four-annotator reliability, while the [paired sample annotations](https://raw.githubusercontent.com/chaitanya2334/WLP-Dataset/master/train/protocol_100.ann) and [step text](https://raw.githubusercontent.com/chaitanya2334/WLP-Dataset/master/train/protocol_100.txt) expose actual offsets and event-argument links. The 622 lab protocols are specialized; the extracted title and linewise instructions are not verified whole manuals. Its entity/action alpha 0.7599 and relation alpha 0.6625 concern those precise annotation tasks, not function agreement. The [2020 reannotation](https://aclanthology.org/anthology-files/pdf/wnut/2020.wnut-1.33.pdf) deduplicates earlier records and adds a test set; it is not an independent 726-document corpus in addition to the old one. [OpenPI](https://github.com/allenai/openpi-dataset) supplies human-vetted state-change tuples `(entity, attribute, before, after)` from wikiHow contexts, useful for testing whether instruction outcomes and dependencies are captured. Its excerpts and inferences are neither paragraph functions nor whole-document quality evidence. In each case, rights to original third-party text need separate clearance.

3. **Use DITA to seed an optional procedure model and deterministic checks.** The [2010 OASIS task specification](https://docs.oasis-open.org/dita/v1.2/spec/DITA1.2-spec.pdf) distinguishes `prereq`, `context`, `steps`, `step`, `cmd`, `info`, `substeps`, `tutorialinfo`, `stepxmp`, `choices`, `stepresult`, `result`, `example` and `postreq`. It distinguishes the strict task body from the more flexible general task body; a `stepsection` is expository rather than a step. The model offers directly actionable field meanings and parser fixtures for explicitly DITA-conformant text, and supports F02/F07/F08/F09 pilot coding. A valid XML structure is not evidence that the steps work, the audience understands them, or every field belongs in a non-DITA procedure. Use reader walkthroughs and domain review for those questions.

[Diátaxis](https://diataxis.fr/application/) offers independently motivated purpose labels—tutorial, how-to guide, reference, explanation—to compare with the project's provisional forms; it is a practitioner framework, not a measured distribution. [Cummaudo et al.](https://nzjohng.github.io/publications/papers/esem2019.pdf) map 21 API-documentation studies into 34 recommendations in five dimensions. Use them as prompts for expert review of usage, rationale, domain knowledge, artifacts and presentation, not as scored universal obligations. [Wang et al. 2023](https://aclanthology.org/2023.emnlp-main.246/) offers a complementary human judgment of whether an individual step is essential to a goal; its release and full coding protocol still need direct inspection before reuse.

## Work still needed

Select and screen complete, version-pinned tutorial, how-to and reference units across independent projects and audiences. Measure section boundaries, whole-body proportions and presentation formats after checking parsers; do not infer those distributions from fragments or schemas. Pilot expert crosswalks between existing content labels and the project's form/section/function layers, including mixed and unresolved cases. Separate boundary and label agreement and evaluate held-out authors or projects. Validate executable checks against human task walkthroughs; do not make semantic labels or observational frequencies into quotas. No source here establishes quality-conditioned proportions across documentation forms.

Repository MIT license files exist for READMEClassifier and WLP, but neither automatically establishes original README/protocol rights; annotation-specific terms remain uncertain. OpenPI's code, annotations and original wikiHow text licenses were not verified. Reuse source documents only after resolving those rights. No large repository or corpus was cloned.

## Access and follow-up

All eight cited papers, standards or descriptions are accessible; no new paywalled synthesis is needed for these leads. The known API reference knowledge study, **Walid Maalej and Martin P. Robillard, “Patterns of Knowledge in API Reference Documentation” (2013), DOI [10.1109/TSE.2013.12](https://doi.org/10.1109/TSE.2013.12)**, remains a valuable library-ready lead and a known baseline. The institutional [dataset index](https://cado.informatik.uni-hamburg.de/data-sets/) failed certificate validation in direct access and timed out through the browsing tool on this pass; this is an access failure, not evidence that the coding data are unavailable. Prior baseline records report 5,574 units and no source text redistribution; reverify the actual guide and terms before relying on them. The 2023 step-essentiality data artifact and annotation license were not directly inspected, so this is a research lead rather than an immediately reusable dataset.
