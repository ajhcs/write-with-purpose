# Mechanical checks

For a requested exact check, reuse the existing `write-with-purpose/scripts/check_text.py` helper when it is available in a known configured skill root. Read its usage or run `--help` if needed. The editor has no required service or helper installation and can work without the writing skill. If the helper is unavailable, use an available counter on the final scoped text or identify the material verification limit and continue the editorial work. A standard-library whitespace-token count, excluding an initial UTF-8 BOM, can verify a declared word ceiling or compare original and final counts without claiming helper contract enforcement.

```text
python <writer-skill>/scripts/check_text.py <edited.txt> [--source <before-or-source.txt>] [--contract <contract.json>] [--enforce-contract]
```

The helper reports exact duplicate prose paragraphs, explicit unresolved markers, limited internal Markdown-anchor discrepancies and source-number differences. Checker 0.2.0 accepts only `protected_literals`, `max_words` and `max_growth_words` contract keys. For a no-growth requirement use `{"max_growth_words": 0}` with the original draft as `--source`. An exact wording obligation can use `{"protected_literals": [{"text": "required wording", "min_count": 1}]}`; a request to preserve an idea does not justify this lock. `--enforce-contract` exits 1 when a declared literal or word limit fails, 2 for unavailable/invalid inputs, and 0 when the declared checks pass; unrelated observations remain advisory. Without enforcement, exit 0 does not mean there are no findings. Inspect `contract_enforcement` and each relevant check's status.

Counts cover whitespace-separated tokens in the entire raw artifact, including markup/code, with an initial UTF-8 BOM excluded. Isolate the actual counted body when the brief excludes headings, references or notes; the helper does not infer those exclusions. Another obligation, such as a minimum word count or required placement, needs a separate supported check. Check the installed helper's flags; do not claim enforcement if an older version cannot run it. Its `input.sha256` identifies the checked bytes, not semantic correctness, author approval or a later chat response.

Use contracts for actual obligations. A selected explanation need not retain every source number, and a justified omission is not a reason to restore a fact mechanically. Interpret findings in context; retain good writing where an observation has no editorial consequence. Check final bytes again if changes make an earlier receipt stale. Confirm separately that a checked body is the intended delivery scope; a file hash does not bind an unchecked chat answer or export. Review placement, attribution, conditions and meaning separately even when literals and limits pass. The helper is read-only, with no installed hook or automatic repair loop. Ordinary delivery needs no checklist log.

When a local spelling or grammar engine is available, record its version, dialect, dictionary and configuration with the input hash. Treat its spans and replacements as proposals. A spelling suggestion can name a different technical concept; verify the intended term before accepting it. Preserve deliberate punctuation and repetition when they serve the passage. A clean grammar report does not settle sentence meaning or reader benefit. Such an engine is not a required dependency of this skill.
